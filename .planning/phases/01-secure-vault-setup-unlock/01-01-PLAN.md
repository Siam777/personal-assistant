## Phase Goal

**Goal (verbatim from ROADMAP.md Phase 1):** Users can create a master-password-protected vault
and unlock it safely, with real encryption at rest and session auto-lock guarding every entry that
will ever be stored in it.

> **MVP-mode note for the developer:** `MVP_MODE` is enabled for this phase, but the ROADMAP
> `**Goal:**` line above is not written in canonical user-story form
> (`As a … I want to … so that …`). Per the MVP planning rules the planner does **not** invent a
> user story. If you want the story form, run `/gsd mvp-phase 1` and re-plan; the four plans in
> this phase are valid either way and are already decomposed as vertical slices.

<objective>
Stand up the Walking Skeleton's structural half: a two-workspace repository that builds, lints,
type-checks, and tests; an Express API that is provably reachable only from loopback; a logging
surface that mechanically cannot emit key material; and the type contracts every later plan in this
phase implements against.

This plan ends with a real, if thin, end-to-end path: a browser page fetches state from the local
API through the Vite proxy and renders it. Plan 01-02 threads real crypto and a real encrypted
database through that same path.

Purpose: the two things that are catastrophic to get wrong late — the network binding and the
logging surface — are made structurally impossible here, before there is any secret to leak. The
Argon2id cost parameters are also measured on real hardware now, so the phase's ~0.5-1s unlock
target is a number rather than an assumption.

Output: a runnable scaffold (`npm run dev`), a calibrated `KDF_PARAMS` constant, and the committed
type contracts.
</objective>
