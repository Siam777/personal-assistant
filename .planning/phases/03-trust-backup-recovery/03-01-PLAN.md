# Plan 03-01: Audit Logging Subsystem

**Phase:** 3 — Trust, Backup & Recovery
**Wave:** 1
**Requirement:** TRUST-03

## Goal
Implement a robust, privacy-preserving audit logging subsystem in SQLite that records vault lifecycle and entry access events (unlock, lock, create, view, update, delete, reveal, copy, 2fa, backup) with zero secret leakage, exposed via `GET /api/vault/audit`.

## Tasks

1. **Database Schema & Table Initialization**
   - Update `server/src/modules/db/schema.ts` to include `audit_logs` interface:
     - `id`: string (UUID)
     - `event_type`: string
     - `entry_id`: string | null
     - `entry_name`: string | null
     - `entry_type`: string | null
     - `details`: string | null (JSON string for non-sensitive metadata)
     - `ip_address`: string | null
     - `user_agent`: string | null
     - `created_at`: string (ISO 8601)
   - Update `initSchema` in `server/src/modules/db/connection.ts` to create `audit_logs` table and index on `created_at` and `entry_id`.

2. **Audit Logging Service & Helper**
   - Create `server/src/modules/audit/audit.ts` with helper:
     - `recordAuditEvent(db: Kysely<VaultDbSchema>, event: AuditEventInput)`
     - Ensures no secret parameters are accepted or recorded.
     - `getAuditLogs(db, { limit, offset, eventType, entryId })`

3. **Event Recording in Vault Endpoints**
   - In `server/src/modules/auth/routes.ts`: log `vault_unlocked`, `vault_locked`, `two_factor_enabled`, `two_factor_disabled`.
   - In `server/src/modules/vault-entries/routes.ts`:
     - On create entry: log `entry_created`
     - On get single entry: log `entry_viewed`
     - On update entry: log `entry_updated`
     - On soft-delete / permanent delete: log `entry_deleted`
     - Add endpoint `POST /api/vault/entries/:id/audit-event` (or `POST /api/vault/audit/events`) to record client events like `secret_revealed` and `secret_copied` safely.
   - Add endpoint `GET /api/vault/audit` protected by `requireUnlocked`.

4. **Testing**
   - Create `server/src/modules/audit/audit.test.ts` verifying:
     - All audit events are recorded properly.
     - `GET /api/vault/audit` returns chronological events.
     - Filter by `eventType` and `entryId` works.
     - No secret payloads exist in audit log data.

## Verification
- Run `npm test` and verify all tests pass.
