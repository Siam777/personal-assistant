**`schemas.ts`** — export `entryUpdateSchema` as a `z.discriminatedUnion("type", [...])` with the same four branches and the same field shapes as `entryCreateSchema`. This is a full-representation update: the client always submits every mutable field, so a partial-merge contract would add ambiguity with no caller. Export the inferred `EntryUpdateInput` type.

**`entries.ts`** — add three exported functions over `getDb()`:
`getEntry(id: string): Promise<Entry | null>` — selects all columns from `entries` where `id` matches and `deleted_at is null`, returning `rowToEntry(row)` or null. This is the only function in the module that reads the `payload` column.
`updateEntry(id: string, input: EntryUpdateInput): Promise<Entry | null>` — reads the existing row first; returns null when it is absent or soft-deleted. When `input.type` differs from the stored row's `type`, throw a tagged error the route converts to 400 — entry type is immutable after creation, because a type change would silently orphan the stored payload shape. Otherwise updates `name`, `folder_id`, `notes`, and `payload` (re-serialized with `JSON.stringify`), sets `updated_at` to a fresh ISO timestamp, and returns the mapped entry. It updates in place: calling it twice with the same body leaves exactly one row.
`softDeleteEntry(id: string): Promise<boolean>` — sets `deleted_at` to a fresh ISO timestamp where the id matches and `deleted_at is null`, returning whether a row was affected. It never issues a `deleteFrom` — the row survives, per D-04.

**`routes.ts`** — add three routes to `entriesRouter`, all inheriting the router-level `requireUnlocked` gate and all using the established async-error wrapper:
`GET /entries/:id` — 200 with the entry, or 404 `{ error: "Entry not found" }`.
`PATCH /entries/:id` with `validate(entryUpdateSchema)` — 200 with the updated entry; 404 when absent or already trashed; 400 `{ error: "Entry type cannot be changed" }` when the immutable-type rule is violated.
`DELETE /entries/:id` — 204 with no body on success, 404 when the entry is absent or already trashed.
Keep using explicit status plus an `{ error: string }` body for these not-found and rule-violation cases rather than routing them through the unlock-oracle error constructor.

3. `card` idempotency — the same, for a card body.
4. Concurrency — fire ten login creates and ten card creates as unawaited promises, `Promise.all`, then assert the list length is exactly 20.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → Express API (`/api/vault/entries/:id`) | The single-entry fetch is the only path that returns decrypted secret values across this boundary |
| rendered DOM → the human at the screen | A revealed secret is readable by anyone with line of sight or a screenshot tool for as long as it stays revealed |
