**`PasswordGenerator.tsx` (new)** — export two things.

*The pure function.* `generatePassword(options: { length: number; upper: boolean; lower: boolean; numbers: boolean; symbols: boolean }): string`. Build the alphabet by concatenating only the enabled classes: uppercase `A` through `Z`, lowercase `a` through `z`, digits `0` through `9`, and the symbol set `!@#$%^&*()-_=+[]{};:,.<>?`. Do not remove characters for being visually confusable and do not filter the output after generating — either would silently cut the entropy below what the user's settings imply. Draw each index with rejection sampling over `crypto.getRandomValues` on a `Uint8Array`: compute the largest multiple of the alphabet length that fits in 256, discard any byte at or above it, and take the remainder of the accepted byte. A plain remainder over an unfiltered byte is a modulo bias and is not acceptable here. Guarantee coverage by placing one character drawn from each enabled class first, filling the rest from the full alphabet, then shuffling the whole array with a Fisher-Yates pass whose swap indices come from the same rejection-sampled source. Throw when no class is enabled — the UI prevents this, and the function must not invent a fallback alphabet. `Math.random` must not appear anywhere in this file.

*The component.* A default-exported trigger plus popover. The trigger is an icon-only `Button` (lucide `Dices`) sized to the 44x44px minimum touch target, intended for the `InputGroup` addon slot. It takes an `onUse(value: string)` prop. The popover body contains: a `Slider` for length with range 8 to 64, default 20, and the current value shown numerically beside it; four `Switch` toggles labelled "Uppercase", "Lowercase", "Numbers", "Symbols", all on by default; a live preview of the current value in the monospace stack with `break-all`; a "Regenerate" button; and a primary "Use this password" button that calls `onUse` and closes the popover. Regeneration is synchronous and instant, so there is no loading state — the preview simply changes. When every toggle is off, the preview area shows the inline note "Select at least one character type" and both "Regenerate" and "Use this password" are disabled. Regenerate the preview automatically whenever the length or any toggle changes. "Use this password" is the only accented control in the popover.

**`EntryForm.tsx`** — wrap each secret-accepting field in an `InputGroup` with the generator in its trailing addon slot, and wire `onUse` to write the value into that field's form state: the `login` password field, the `api_key` key field, and the `card` number and CVV fields. Do not attach it to Name, Notes, Endpoint, Model, Username, URL, Expiry, Cardholder, or the note body — those do not accept a generated secret. Each generator instance holds its own popover state so opening one does not affect another.

**`entries.ts`** — add four exported functions:
`restoreEntry(id)` — clears `deleted_at` back to null where the id matches and `deleted_at is not null`; returns the restored entry or null. Folder and tag links are untouched, so a restored entry comes back exactly where it was.
`permanentlyDeleteEntry(id)` — inside one `db.transaction()`, deletes the `entry_tags` rows for that entry, then the `entries` row; returns whether anything was removed. It requires `deleted_at is not null`, so a live entry can never be destroyed through this path.
`emptyTrash()` — the same two deletes scoped to every entry with a non-null `deleted_at`, in one transaction, returning the number removed.
`purgeExpiredTrash(db, now = new Date())` — takes the database handle explicitly rather than calling `getDb()`, because it runs during vault open before the session singleton has taken ownership of the handle. It computes the cutoff from `TRASH_RETENTION_DAYS`, then in one transaction deletes the `entry_tags` rows for, and then the rows of, every entry whose `deleted_at` is strictly older than the cutoff. Entries deleted inside the window are untouched.

**`bootstrap.ts`** — after the existing `initSchema(db)` call, add `await purgeExpiredTrash(db)`. This is the reason the seam exists; the auth routes are not touched again.
