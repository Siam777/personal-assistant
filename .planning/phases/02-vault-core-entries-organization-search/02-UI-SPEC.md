## Spacing Scale

Declared values (must be multiples of 4), Tailwind's default scale (`p-1`=4px … `p-16`=64px):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps, badge/tag internal padding |
| sm | 8px | Compact element spacing (form field internal gaps, tag chip gaps) |
| md | 16px | Default element spacing (form field stacking, card padding) |
| lg | 24px | Section padding (panel/card outer padding, dialog padding) |
| xl | 32px | Layout gaps (gap between sidebar and main content, gap between page header and content) |
| 2xl | 48px | Major section breaks (between page title block and entry grid) |
| 3xl | 64px | Page-level spacing (top padding on empty-state screens) |

Exceptions:
- Icon-only buttons (reveal secret, copy, tag remove-x, folder overflow menu) use a **44x44px minimum touch target** even though the visible icon is 16-20px — accessibility floor, not a spacing-scale violation (the extra area is padding, itself a multiple of 4: 44 = icon(20) + padding(12*2)).
- Tag chips and the search input use `radius: default` (0.625rem / 10px) per the shadcn preset's `--radius` token — not part of the spacing scale but noted since it's a fixed non-4px value baked into the design system.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 (regular) | 1.5 |
| Label | 14px | 600 (semibold) | 1.4 |
| Heading | 20px | 600 (semibold) | 1.3 |
| Display | 28px | 600 (semibold) | 1.2 |

Only 2 weights used across the whole phase (400, 600) — no 500/700 anywhere. Mapping to elements:
- **Display (28/600/1.2):** Page-level title only ("Vault", empty-state headline)
- **Heading (20/600/1.3):** Entry detail title, dialog titles ("New API key entry", "Edit folder"), section headers ("Folders", "Tags", "Trash")
- **Label (14/600/1.4):** Form field labels, entry list metadata (folder name, tag chips, "Updated 2 days ago"), table/column headers
- **Body (16/400/1.5):** Entry field values, form input text, search results, notes content, all body copy

A monospace override applies to **secret values only** (API key, password, card number when revealed) — not a new size/weight, just `font-mono` (system monospace stack) at Body size, to make character-by-character scanning of secrets accurate (a well-established security-UI pattern: 1Password, Bitwarden both do this).

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--background` — `oklch(1 0 0)` white / `oklch(0.145 0 0)` near-black (dark) | Page canvas, main content area background |
| Secondary (30%) | `--card` / `--sidebar` — `oklch(0.97 0 0)` light gray / `oklch(0.205 0 0)` dark gray | Folder sidebar, entry cards/rows, dialog surfaces, tag chip background (unselected) |
| Accent (10%) | `--primary` — `oklch(0.457 0.24 264.389)` ≈ `#4F46E5` indigo-600 (light) / `oklch(0.673 0.182 276.935)` ≈ `#818CF8` indigo-400 (dark) | See reserved-for list below — this is the ONE color hue in the whole UI besides neutral gray and destructive red |
| Destructive | `--destructive` — `oklch(0.577 0.245 27.325)` ≈ `#DC2626` red-600 (light) / `oklch(0.704 0.191 22.216)` ≈ `#F87171` red-400 (dark) | Delete entry/folder, empty trash, disable 2FA — destructive actions only |

**Accent (indigo) reserved for — explicit list, nothing else:**
1. Primary CTA buttons: "New entry", "Save", "Create folder", "Generate password" / "Use this password"
2. Active/selected state: the currently-selected folder in the sidebar, the currently-active tag filter chip
3. Focus ring (`--ring`) on any focused interactive element (inputs, buttons, tag chips) — accessibility, not decoration
4. Search input's focused border and the entry-count badge on an active search/filter
5. Links/inline actions that navigate (e.g. "View trash" link)

Everything else — entry type icons, card borders, secondary buttons ("Cancel", "Copy", filter toggles), unselected folder/tag rows — stays neutral gray. This scarcity is deliberate: in a vault UI, the accent color should draw the eye to *the one action that matters on this screen*, not compete with itself.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | "New entry" (opens type picker: API key / Login / Secure note / Card) |
| Empty state heading (no entries yet) | "Your vault is empty" |
| Empty state body (no entries yet) | "Add your first API key, login, note, or card to get started." + "New entry" button |
| Empty state heading (search/filter, no matches) | "No matches" |
| Empty state body (search/filter, no matches) | "No entries match \"{query}\". Try a different search term or clear your filters." + "Clear filters" button |
| Empty state (folder, no entries) | "This folder is empty. Move entries here or create a new one." |
| Empty state (trash) | "Trash is empty" / "Deleted entries are kept for 30 days, then removed automatically." |
| Error state (entry load/save failure) | "Couldn't save this entry. Check your connection and try again." — generic message, never leaks which field/query failed at the crypto layer, consistent with Phase 1's "generic unlock failure" precedent |
| Error state (search failure) | "Search is temporarily unavailable. Your entries are safe — try again in a moment." |
| Destructive confirmation — delete entry | "Move to trash?" / "\"{entry name}\" will move to Trash and be permanently deleted after 30 days. You can restore it anytime before then." — Confirm: "Move to trash" / Cancel: "Cancel" |
| Destructive confirmation — permanently delete (from trash) | "Delete forever?" / "This cannot be undone. \"{entry name}\" and its contents will be permanently erased." — Confirm: "Delete forever" (destructive-styled) / Cancel: "Cancel" |
| Destructive confirmation — delete folder | "Delete folder?" / "\"{folder name}\" will be deleted. Entries inside it will become uncategorized, not deleted." — Confirm: "Delete folder" / Cancel: "Cancel" |
| Destructive confirmation — empty trash | "Empty trash?" / "All {N} items in Trash will be permanently deleted. This cannot be undone." — Confirm: "Empty trash" (destructive) / Cancel: "Cancel" |

**Note on secret-reveal UX** (Claude's-discretion item from `02-CONTEXT.md`): entry detail fields for secret values (password, API key, card number/CVV) render **masked by default** (`•••••••••`) with a per-field eye-icon toggle to reveal. Revealing one field does not reveal others. Revealed state **auto-re-masks after 30 seconds of inactivity** or immediately on navigating away from the entry — consistent with the vault's "always safe" core value and Phase 1's precedent of aggressively re-locking rather than leaving sensitive state exposed.

**Note on password generator placement** (Claude's-discretion item): inline on the password/login-password field and the card-CVV/number field as a small dice icon button inside the input (`input-group` component), opening a popover with a length slider (default 20, range 8-64) and four toggles (uppercase / lowercase / numbers / symbols, all on by default) plus a live-generated preview and "Use this password" button. Not a standalone top-level tool — it only ever appears attached to a field that accepts a generated secret.
